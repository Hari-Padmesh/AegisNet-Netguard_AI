iApplication-layer monitoring. NetGuard observes HTTP requests passing through its integration. It does not inspect unrelated network traffic or replace a firewall.

One request, several layers of visibility

NetGuard combines fast request rules with flow-level model scoring, then publishes results through logs, alert channels, and dashboards.

01

Observe

Middleware reads client IP, method, path, query string, status, and request/response sizes.

02

Check rules

Deterministic HTTP rules detect suspicious paths and request bursts.

03

Score flows

Requests are grouped by client and destination port, then mapped to model features.

04

Report

Alerts can go to console, file, email, webhooks, Slack, or a live dashboard.

DATA SCOPENetGuard records request metadata and size measurements; it does not need request or response bodies. Rules inspect path and query. Recent dashboard events include path, method, client IP, label, confidence, and detection source.

Quick start

Create a guard, attach it to FastAPI, then configure dashboard authentication.

PYTHON 
from fastapi import FastAPI
from netguard import NetGuard, NetGuardConfig
from netguard.integrations.fastapi import setup_netguard

app = FastAPI()
guard = NetGuard(config=NetGuardConfig.from_env())
setup_netguard(app, guard)
POWERSHELL 
$env:NETGUARD_AUTH_USERNAME = "admin"
$env:NETGUARD_AUTH_PASSWORD = "use-a-long-secret"
uvicorn main:app --host 127.0.0.1 --port 8000

Open http://127.0.0.1:8000/netguard/. The dashboard uses browser Basic Auth and displays events after the app receives traffic.

Rules, model scoring, and blocking

NetGuard evaluates application-level rules on each observed request. It also aggregates request and response sizes into approximate network-flow features for the bundled model, which is based on CICIDS-style flow data. These are complementary signals, not full packet inspection or a substitute for packet capture.

RuleObserved signalDefault behavior
SQL injectionSuspicious SQL keywords, comments, or common tautologies in path/query.High-confidence web attack event.
Cross-site scriptingScript tags, javascript URLs, and common inline event handlers in path/query.High-confidence web attack event.
Path traversalParent-directory sequences and common sensitive system file paths.High-confidence web attack event.
Failed authentication burstAt least 5 responses with status 401/403 on recognized authentication paths within the configured window.Brute-force event.
Sensitive path scanAt least 3 unique sensitive paths probed by one client in the configured window.Port-scan event.
Request burstAt least 25 requests from one client within 2 seconds.DoS-like event.
Flow modelAggregated request/response byte sizes, counts, and destination port.Scores when a flow closes after inactivity or app shutdown.

The default flow window is 30 seconds. The failed-auth and sensitive-path thresholds use this window. Rule cooldowns suppress duplicate notifications per client and rule; detections remain visible in recent events. Tune thresholds and review false positives before relying on alerts for operational decisions.

IMPORTANTA detection does not automatically block that client. NetGuard exposes explicit IP block/unblock controls; applications can also call guard.block_ip(ip, duration_seconds=300). Blocks are in-memory and apply to the instrumented process.

Client IP behind a proxy

NetGuard uses the first address in X-Forwarded-For when present, otherwise the connection peer address. Only accept forwarded headers from a trusted proxy that overwrites client-supplied values.

Reverse proxy

Inspect proxied HTTP requests without raw packet capture.

TERMINAL 
netguard proxy --target http://127.0.0.1:3000 --host 127.0.0.1 --port 8080 --project-id web-app --auth-username admin --auth-password "replace-this-secret"

Route clients through port 8080. The dashboard is under /netguard/. Use TLS and prevent direct access to the upstream in production.

Email and weekly digest

Choose SMTP or the Resend HTTPS API. Resend is an alternative when a host blocks SMTP. FastAPI starts and stops the weekly scheduler with app lifespan when the selected provider is configured.

RESEND API · POWERSHELL 
$env:NETGUARD_EMAIL_PROVIDER = "resend"
$env:NETGUARD_ALERT_EMAIL = "security@example.com"
$env:NETGUARD_RESEND_API_KEY = "re_your_secret_api_key"
$env:NETGUARD_RESEND_FROM = "onboarding@resend.dev"
$env:NETGUARD_WEEKLY_DIGEST_ENABLED = "true"
$env:NETGUARD_WEEKLY_DIGEST_DAY = "sun"
$env:NETGUARD_WEEKLY_DIGEST_HOUR = "9"

Resend's test sender can be used to test delivery to the email address associated with your Resend account. For other recipients, verify a sender domain and set NETGUARD_RESEND_FROM to an address on it. The HTTPS API supports immediate alerts and digests. Use one scheduler process per app to avoid duplicate digests. Keep API keys secret.

SMTP configuration

For SMTP providers, set NETGUARD_EMAIL_PROVIDER=smtp, NETGUARD_SMTP_HOST, NETGUARD_SMTP_PORT, NETGUARD_SMTP_USER, and NETGUARD_SMTP_PASSWORD. Keep SMTP credentials secret.

Deployment checklist

01 Install netguard-threat-monitor[web] in the app environment.

02 Load dashboard credentials from a secret manager.

03 Choose embedded mode or a private central dashboard.

04 Persist and back up netguard-projects.sqlite3.

05 Use TLS and network controls for dashboards and proxy traffic.

06 Run one weekly scheduler per application.

NetGuard analyzes HTTP requests observed by its integration. Pair it with network security controls for broader coverage.

Troubleshooting

The dashboard shows no client IPs or requests

Send traffic through the instrumented app. A central dashboard only displays apps configured to report to its URL. Check project ID, mode, endpoint, and credentials.

Authentication fails

Set username and password, or an API key. Use matching credentials between app and central server.

Dashboard dependencies are missing

Install netguard-threat-monitor[web] in the application environment.

No email digest arrives

Check the selected provider, API key or SMTP credentials, and recipient. Verify FastAPI lifespan and one scheduler worker. Try netguard digest --send.

Live packet capture is denied

Windows raw socket capture needs elevated privileges. Framework and proxy modes do not.

?Bug reports should include NetGuard/Python versions and a sanitized trace. Never share secrets.

$env:NETGUARD_AUTH_USERNAME = "admin"

Open http://127.0.0.1:8000/netguard/ and sign in as admin / secret.

TERMINAL 2 · SEND TRAFFIC 
cd D:\nids-project
.\.venv\Scripts\python nids-project\examples\fastapi_demo\simulate_traffic.py

The simulator sends ordinary requests, SQL injection, XSS, path traversal, scanner probes, and periodic request bursts. Watch request counts and security events update. The simulator does not automatically block detected clients. Press Ctrl+C to stop it.
