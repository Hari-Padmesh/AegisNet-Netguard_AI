Add NetGuard to FastAPI

Use this for an existing FastAPI app that should host the embedded dashboard at /netguard/.

COPY PROMPT 
I want to add NetGuard threat monitoring to this existing FastAPI application.

First inspect the repository: identify the application entry point, dependency manager, ASGI server command, existing middleware order, deployment platform, and current tests. Do not replace routes, authentication, database code, or deployment configuration unrelated to this task.

Use the published package `netguard-threat-monitor[web]` (Python import name `netguard`). Integrate the current public API using `NetGuardConfig.from_env(project_id="[PROJECT NAME]")`, `NetGuard(config=config)`, and `setup_netguard(app, guard)` from `netguard.integrations.fastapi`. Preserve the existing app object and route behavior. Keep the dashboard at the configured `/netguard` path and ensure its Basic Auth credentials come from environment variables or the deployment secret manager.

Document the exact dependency and start command for this repository. Add only the minimum code/config needed. Do not hardcode or commit passwords, API keys, SMTP passwords, or Resend keys. Do not enable automatic IP blocking unless I explicitly request it. Explain what requests NetGuard observes, where the dashboard is, and any proxy/client-IP trust assumptions.

At the end, summarize changed files, environment variables I must configure, local commands to run, and focused verification steps. Do not deploy or publish anything.

Add NetGuard to Django

The current Django integration is middleware-oriented. It does not mount the embedded dashboard; ask the agent to configure central reporting if you need a browser dashboard.

COPY PROMPT 
Integrate NetGuard into this existing Django project.

Inspect the Django version, settings modules, installed apps, middleware list, WSGI/ASGI entry point, environment management, deployment platform, and tests before editing. Preserve the project's existing middleware and request behavior.

Use `netguard-threat-monitor[web]`. Add `netguard.integrations.django.NetGuardDjangoMiddleware` to the middleware stack in an appropriate position, and configure NetGuard using documented `NETGUARD_*` environment variables. Keep all credentials in the host's secret manager; do not write secret values into source files.

Important: the current Django middleware observes traffic and honors NetGuard IP blocks, but it does not mount the embedded `/netguard/` dashboard. If a dashboard is wanted, explain and configure the supported separate dashboard reporting mode, including project ID, dashboard URL, matching authentication/API-key settings, and a secure network path. Do not claim that simply adding the middleware creates a dashboard in Django.

Make the smallest necessary changes. Add or update setup documentation and focused tests if the repository already has an appropriate test pattern. Do not enable automatic blocking unless explicitly requested. Finish with changed files, required environment variables, local run commands, deployment settings, and verification steps. Do not deploy.

Add NetGuard to Flask

This uses the separate, legacy Flask extension in netguard.integrations.flask.

COPY PROMPT 
Add the NetGuard Flask extension to this existing Flask application.

Inspect the app factory, Flask version, routing, reverse proxy setup, dependencies, deployment configuration, and tests first. Preserve all current routes and request handling.

Install/configure `netguard-threat-monitor[flask]` and integrate `NetGuardFlask` from `netguard.integrations.flask`. Support this project's app-factory pattern by calling `init_app(app)` where appropriate. Keep `block_attacks=False` unless I explicitly approve automatic blocking, and configure any alert webhook or log path through secrets/settings rather than hardcoded values.

Security requirement: the current legacy Flask dashboard/API routes do not provide built-in authentication. Default to `dashboard=False` for a public production deployment unless you can place those routes behind the app's existing authentication or a trusted access-control proxy. Explain the selected mount path and how to verify that dashboard routes are protected.

Make the smallest required changes. Do not replace the project's auth, routes, or deployment process. Summarize changed files, dependency changes, environment variables/secrets, local verification commands, and known limitations. Do not deploy or publish.

Prepare data, train, and evaluate

Use this when you have authorized CICIDS-style CSV data and want the agent to make the data/model workflow reproducible.

COPY PROMPT 
Help me use NetGuard's training and evaluation functions with my local network-flow CSV dataset.

Inspect this repository's NetGuard version, dataset files and licenses, CSV column names, label column, available disk/RAM, existing model artifacts, and training scripts before running anything. Do not upload data. Do not overwrite existing models or processed data until you explain the output paths and I approve.

Use the supported `netguard-threat-monitor[train]` extra and the existing public functions: `load_and_clean`, `encode_labels`, `split_data`, `select_features_by_importance`, `scale_features`, and `train_pipeline` in their documented modules. For evaluation use `run_evaluation` and its stored test set. Check that labels and feature columns are compatible with NetGuard's expected model inputs. Do not invent metrics or claim model quality from training accuracy alone; report macro-F1 and per-class false-positive rates where available.

Prepare a safe, reproducible command sequence and explain dataset placement, expected runtime/memory, model output files, and how to roll back to the bundled model. Ask before launching a long-running training job or replacing artifacts. Do not publish datasets or model files.

Deploy the Python app to Render

Use this for a Python web service. The documentation site itself uses a separate static-site deployment described in the API reference.

COPY PROMPT 
Prepare this FastAPI application, integrated with NetGuard, for deployment as a Render Web Service.

Inspect the repository root, requirements/lock file, Python version, FastAPI entry point, NetGuard configuration, and existing deployment files. Determine whether this is a monorepo and identify the correct Render root directory. Do not assume the service source is at the repository root.

Make only necessary deployment changes. Confirm that production dependencies include `netguard-threat-monitor[web]` and any currently required runtime dependencies. Use a production Uvicorn command binding to `0.0.0.0` and Render's `$PORT`; do not use `--reload`. Keep `NETGUARD_AUTH_USERNAME`, `NETGUARD_AUTH_PASSWORD`, and any email-provider API key in Render Environment secrets, never in Git. Include a secure health check only if the app has an appropriate route.

Do not create or modify a paid service, push commits, connect an account, or deploy. Give me the Render dashboard values for Root Directory, Build Command, Start Command, and required Environment keys, plus local verification commands and expected app/dashboard URLs.
